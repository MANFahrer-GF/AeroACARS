## 🇩🇪 Deutsch

### Erst aktualisieren, dann fliegen

Liegt beim Start eine neuere Version vor, fragt AeroACARS ab sofort
nicht mehr höflich — es kommt eine Meldung mit einem Knopf
**„Update durchführen"**, und weiter geht es danach.

Der Grund ist nicht Bequemlichkeit. AeroACARS bewertet Landungen und
reicht Flüge ein. Wer wochenlang auf einem alten Stand fliegt, erzeugt
Werte, die sich später nicht mehr zuordnen lassen — und meldet Fehler,
die längst behoben sind.

**Wann die Meldung ausbleibt** — jeder dieser Fälle ist Absicht:

* **Kein Netz oder GitHub nicht erreichbar.** Dann gibt es nichts zu
  prüfen, und du fliegst wie immer. Ein Ausfall dort darf dich nicht
  aufhalten.
* **Das Update taucht erst mitten in der Sitzung auf.** Der Riegel greift
  nur beim Start. Der Turnus, der alle vier Stunden nachsieht, sperrt
  nie — sonst stündest du womöglich zwischen zwei Flügen davor.
* **Ein Flug läuft.** In jeder aktiven Phase bleibt die Meldung weg.
* **Die Installation scheitert.** Dann erscheint „Trotzdem fortfahren".
  Ohne diesen Ausweg wäre der Client für jemanden mit klemmendem Updater
  unbenutzbar — und zwar ohne Weg zurück.

Ein „Später" gibt es bewusst nicht: Das wäre wieder das Banner, und das
gibt es schon.

⚠ Wirksam wird das **ab dem nächsten** Update. Diese Version bringt den
Riegel mit; sperren kann er erst, wenn es etwas Neueres gibt.

### CARTO verlangt einen Schlüssel — der liegt jetzt auf dem Server

CARTO, woher die Live-Karte und die Logbuch-Karte ihre Grundlage
beziehen, verlangt seit dem 26.08.2026 einen API-Schlüssel. Frei bis
fünf Millionen Kacheln im Monat; bei unseren Zahlen weit außer
Reichweite.

Der Schlüssel liegt **auf dem VA-Server**, nicht im Programm. Der Client
holt ihn beim Start und legt ihn lokal ab — genau wie die Farbtabelle.

Für dich ändert sich nichts: Ohne hinterlegten Schlüssel sehen die
Karten aus wie bisher, und ohne Netz greift der lokal abgelegte Stand.
Der Vorteil zeigt sich später — ändert CARTO etwas, tauscht der
VA-Betreiber einen Eintrag aus, und **du brauchst kein Update**.

### Für VA-Betreiber

Im Admin von **aeroacars-live** gibt es unter Einstellungen einen neuen
Abschnitt „Kartengrundlage (CARTO)". Schlüssel eintragen, speichern —
die Piloten übernehmen ihn beim nächsten Start des Clients.

Der Schlüssel wird an **jede** Anfrage an CARTO gehängt, nicht nur an
die Stil-Adresse: Die style.json verweist selbst weiter auf Schriften,
Sprites und eine TileJSON, und die wiederum auf die eigentlichen
Kacheln. Nur die Stil-Adresse zu versehen hätte genau die Kacheln
ungeschützt gelassen, die CARTO zählt.

Bedingung des freien Schlüssels ist die sichtbare Nennung von CARTO und
OpenStreetMap. Sie liefert CARTO in seinen eigenen Kacheldaten mit, und
MapLibre zeigt sie im Attributionsfeld der Karte — geprüft, nicht
angenommen.

Nicht betroffen: die Karte auf dem Server selbst (Esri, OpenStreetMap,
OpenTopoMap).

## 🇬🇧 English

### Update first, then fly

If a newer version is waiting when you start, AeroACARS no longer asks
politely — you get a notice with an **"Install update"** button, and
things continue afterwards.

The reason is not convenience. AeroACARS scores landings and files
flights. Flying an outdated build for weeks produces figures that cannot
be attributed later — and reports of faults that were fixed long ago.

**When the notice stays away** — each of these is deliberate:

* **No connection, or GitHub unreachable.** Then there is nothing to
  check and you fly as usual. An outage there must not stop you.
* **The update only appears mid-session.** The gate applies at startup
  only. The four-hourly re-check never blocks — otherwise you might face
  it between two flights.
* **A flight is running.** In every active phase the notice stays away.
* **The install fails.** Then "Continue anyway" appears. Without that way
  out, a client whose updater is stuck would be unusable, with no way
  back.

There is deliberately no "Later": that would be the banner again, and
the banner already exists.

⚠ This takes effect from the **next** update. This version carries the
gate; it can only block once something newer exists.

### CARTO now requires a key — it lives on the server

CARTO, which supplies the basemap for the live map and the logbook map,
has required an API key since 26 August 2026. Free up to five million
tile requests a month — far beyond our numbers.

The key lives **on the VA server**, not in the program. The client
fetches it at startup and caches it locally, exactly like the colour
palette.

Nothing changes for you: without a key configured the maps look as they
always did, and with no connection the cached values apply. The benefit
comes later — if CARTO changes something, the VA operator swaps one
entry and **you need no update**.

### For VA operators

The **aeroacars-live** admin has a new section under Settings, "Karten-
grundlage (CARTO)". Enter the key, save — pilots pick it up the next
time they start the client.

The key is attached to **every** request to CARTO, not just the style
URL: style.json itself points on to fonts, sprites and a TileJSON, and
that in turn to the actual tiles. Covering only the style URL would have
left exactly the tiles CARTO counts unprotected.

The free key requires visible CARTO and OpenStreetMap attribution. CARTO
ships it in its own tile metadata and MapLibre shows it in the map's
attribution control — verified, not assumed.

Not affected: the map on the server itself (Esri, OpenStreetMap,
OpenTopoMap).
