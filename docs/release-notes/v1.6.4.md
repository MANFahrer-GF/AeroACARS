## 🇩🇪 Deutsch

### Die VATSIM-Sektoren zeichnen wieder — und jetzt weltweit

Kurz und ehrlich: Die Sektoranzeige auf der Karte hat **nie** funktioniert. Seit sie eingebaut wurde, zeichnete sie null Flächen — auf jeder Flugfläche, in jedem Land. Aufgefallen ist es erst, als wir die Zuordnung gegen den echten VATSIM-Feed geprüft haben statt nur gegen den Code.

**Woran es lag:** Wir haben das Rufzeichen falsch gelesen. Der Code suchte die Station im Mittelteil — bei `EDWW_W_CTR` also eine Station namens „W". Die gibt es nicht: Unter dem Kürzel `EDWW` liegen elf verschiedene Stationen mit Namen wie `WWW` oder `ALR`.

Die Datenquelle macht es anders, und das steht auch so in ihrer Doku: Sie wertet nur den Teil **vor** dem ersten Unterstrich aus, den Teil **nach** dem letzten — und unterscheidet die Stationen über die **Frequenz**. `EDWW_W_CTR` auf 127.675 ist damit eindeutig Bremen Radar.

**Und dann fehlte immer noch die halbe Welt.** Balkan, die US-Center, Asien: nichts. Ursache war eine fest verdrahtete Liste von zwölf Ländern im Programm. Das Datenverzeichnis hat 194 Dateien mit rund 28 MB — die kann kein Programm bei jedem Kartenaufruf herunterladen.

Deshalb rechnet das jetzt der Server. Er lädt einmal alles und liefert der Karte nur noch die Flächen der gewünschten Flugfläche. Die Regeln haben wir gegen [VATSIM Radar](https://github.com/daniluk4000/vatsim-radar) abgeglichen, dessen Quelltext offen liegt. Drei Dinge hatten wir anders als die: US-Center und Irland liegen in Unterordnern mit getrennten Dateien; deren Luftraumdaten haben eine andere Form; und Zuständigkeiten dürfen über die Landesgrenze auf ein Nachbarland zeigen. Alle drei waren der Grund für fehlende Flächen.

**Was ihr jetzt seht:** 154 Länderdatensätze, 5844 Stationen, 9118 Luftraumblöcke. Die Sektoren wechseln mit der Flugfläche, jede Station in ihrer eigenen Farbe — dieselben, die auch Lotsen benutzen. Klickt eine Fläche an, steht dort Klarname, Frequenz und das Höhenband.

Wo die Quelle keine Daten hat, bleibt die Karte ehrlich leer, statt eine Fläche zu erfinden. Das betrifft vor allem einige US-Center: von den dortigen Bezirken sind erst dreizehn erfasst.

*Server-Hinweis für VA-Betreiber: Die Karte holt die Sektoren jetzt vom Live-Server (`/api/vatglasses`). Diese Route kam mit demselben Stand auf aeroacars-live dazu und läuft dort bereits.*

## 🇬🇧 English

### VATSIM sectors are drawn again — and now worldwide

Bluntly: the sector display on the map **never** worked. Since it was added it drew zero areas — at every flight level, in every country. It only came to light when we checked the matching against the live VATSIM feed instead of just reading the code.

**The cause:** we read the callsign wrongly. The code looked for the station in the middle part — so for `EDWW_W_CTR` it searched for a station called "W". There is none: eleven different stations sit under the `EDWW` prefix, with names like `WWW` or `ALR`.

The data source works differently, and says so in its documentation: it only evaluates the part **before** the first underscore, the part **after** the last — and distinguishes stations by **frequency**. `EDWW_W_CTR` on 127.675 is therefore unambiguously Bremen Radar.

**And half the world was still missing.** The Balkans, the US centers, Asia: nothing. The cause was a hard-coded list of twelve countries in the app. The data directory holds 194 files totalling some 28 MB — no app can download that on every map view.

So the server does the work now. It loads everything once and hands the map only the areas for the requested flight level. We checked our rules against [VATSIM Radar](https://github.com/daniluk4000/vatsim-radar), whose source is public. Three things we had wrong: US centers and Ireland live in subfolders with separate files; their airspace data has a different shape; and ownership may point across a border to a neighbouring country. All three caused missing areas.

**What you now see:** 154 country datasets, 5844 stations, 9118 airspace blocks. Sectors change with flight level, each station in its own colour — the same ones controllers use. Click an area and you get the spoken name, frequency and altitude band.

Where the source has no data the map stays honestly empty instead of inventing an area. This mainly affects some US centers: only thirteen of those districts are covered so far.

*Note for VA operators: the map now fetches sectors from the live server (`/api/vatglasses`). That route shipped with the same change on aeroacars-live and is already running there.*
