# v1.2.3 — Sicherheitskorrektur und Erreichbarkeitsanzeige

## 🇩🇪 Deutsch

**Wichtig für alle, die PDC/CPDLC nutzen: eine Sicherheitskorrektur. Bitte aktualisieren.**

Bei einem Netzwerkfehler konnte der Hoppie-Logon-Code in der Oberfläche auftauchen. Ursache: Die verwendete HTTP-Bibliothek hängt an ihre Fehlermeldung die vollständige Anfrage-Adresse an — und darin steht der Code. Diese Meldung wurde an einer Stelle als Tooltip angezeigt. Netzwerkfehler erscheinen jetzt nur noch als kurzer Hinweis („Zeitüberschreitung", „Keine Verbindung zum Hoppie-Netz"); die technische Ursache steht weiterhin im ACARS-Log. Betrifft nur eingeschaltetes PDC/CPDLC, und der Code ging nie über das Netz an Dritte — er war lokal sichtbar.

**Neu: Erreichbarkeit der Zielstation.** Neben dem Empfänger-Feld (PDC) und dem Center-Feld (CPDLC) steht jetzt, ob unter diesem Callsign überhaupt jemand am Datalink registriert ist. Vorher war der Fehlerfall völlig stumm: Eine Anfrage an einen unbesetzten Platz lag einfach da, und man wartete auf eine Antwort, die nie kommen konnte.

Die Anzeige sagt bewusst nicht „niemand da". Lotsen wählen ihr Datalink-Callsign frei und geben es im ATIS bekannt — es muss nicht dem Flughafen-Code entsprechen. Steht dort also „Unter EDDF ist nichts registriert", lohnt der Blick ins ATIS. Geprüft wird einmal, nachdem du zu tippen aufgehört hast, nicht laufend: Hoppie wird ehrenamtlich betrieben.

**Der Tab ist weg, wenn du das Feature nicht nutzt.** Bisher war „PDC/CPDLC" immer sichtbar und zeigte nur einen Hinweis auf die Einstellungen. Jetzt erscheint er erst, wenn du das Feature einschaltest. Wer kein Datalink fliegt, sieht die App wie vorher.

**Kleinere Korrekturen:** Der „Prüfen"-Knopf beim Logon-Code ist entfallen — er brauchte ein Callsign vom PDC/CPDLC-Tab und konnte deshalb aus Gründen scheitern, die mit dem Code nichts zu tun hatten. Das Verbinden führt dieselbe Prüfung durch und meldet dasselbe. Außerdem kann ein langsamer Netzwerkaufruf die Bedienung nicht mehr blockieren.

**Für VA-Owner:** Keine Wire-Format-Änderung, `aeroacars-live` muss nicht mit-deployed werden.

## 🇬🇧 English

**Important for anyone using PDC/CPDLC: a security fix. Please update.**

On a network error the Hoppie logon code could surface in the interface. Cause: the HTTP library appends the full request address to its error message — and the code is in it. That message was shown as a tooltip in one place. Network errors now appear only as a short note ("timeout", "no connection to the Hoppie network"); the technical cause still goes to the ACARS log. Only affects PDC/CPDLC when enabled, and the code was never sent anywhere — it was visible locally.

**New: reachability of the target station.** Next to the recipient field (PDC) and the centre field (CPDLC) you can now see whether anything is registered on the datalink under that callsign. Previously this failure was completely silent: a request to an unstaffed position simply sat there while you waited for an answer that could never come.

The indicator deliberately does not say "nobody is there". Controllers pick their datalink callsign freely and advertise it in the ATIS — it need not match the airport code. So if it reads "nothing registered as EDDF", the ATIS is worth a look. The check runs once after you stop typing, not continuously: Hoppie is run by volunteers.

**The tab is gone if you don't use the feature.** "PDC/CPDLC" used to be permanently visible, showing only a pointer to settings. It now appears once you enable the feature. If you don't fly datalink, the app looks exactly as it did.

**Smaller fixes:** the "verify" button for the logon code is gone — it needed a callsign from the PDC/CPDLC tab and could therefore fail for reasons unrelated to the code. Connecting performs the identical check and reports the identical result. A slow network call can also no longer block the interface.

**For VA owners:** no wire-format change, `aeroacars-live` does not need co-deploying.
