## 🇩🇪 Deutsch

Diese Version behebt einen Fehler, durch den das AeroACARS-Fenster einfrieren konnte, und macht die Oberfläche insgesamt robuster.

### Kein Einfrieren mehr beim Schließen oder Minimieren

Wer AeroACARS über das **X** in den Tray schickte, konnte selten ein eingefrorenes Fenster erleben: Nichts reagierte mehr, im Hintergrund lief die App aber weiter, bis man sie beenden musste. Ursache war ein Zusammenstoß beim Speichern von Fenstergröße und -lage. Das Speichern läuft jetzt so, dass es sich nicht mehr mit Fensteraktionen wie Schließen, Minimieren oder Verschieben in die Quere kommen kann.

### Flüssigere Oberfläche

Viele Abläufe, die auf Dateien oder den Simulator warten, laufen jetzt im Hintergrund statt in der Oberfläche. Dazu gehören zum Beispiel der Simulatorwechsel, das Laden von Landungen und Bordbuch sowie das Löschen alter Flug-Logs. Die Oberfläche bleibt dabei bedienbar.

Wird MSFS beim Simulatorwechsel nicht sauber beendet, wartet AeroACARS höchstens drei Sekunden und arbeitet dann normal weiter. Bisher konnte es an dieser Stelle unbegrenzt hängen.

### Hänger werden uns gemeldet

Reagiert die Oberfläche länger als acht Sekunden nicht, schreibt AeroACARS das ins Diagnose-Log. Hast du der Fehlerübermittlung zugestimmt, geht zusätzlich eine kurze Meldung an uns. So finden wir solche Fälle auch, wenn niemand sie meldet.

### Hinweis für VA-Betreiber

Der Client braucht keine Server-Änderung (`aeroacars-live`).

## 🇬🇧 English

This version fixes a bug that could freeze the AeroACARS window and makes the interface more robust overall.

### No more freezing when closing or minimizing

Sending AeroACARS to the tray with the **X** could, in rare cases, freeze the window: nothing responded any more, while the app kept running in the background until it had to be killed. The cause was a clash when saving the window size and position. Saving now works in a way that can no longer collide with window actions such as closing, minimizing or moving.

### Smoother interface

Many tasks that wait for files or the simulator now run in the background instead of in the interface, for example switching simulators, loading landings and the logbook, and deleting old flight logs. The interface stays usable meanwhile.

If MSFS does not shut down cleanly when you switch simulators, AeroACARS now waits at most three seconds and then carries on. Before, it could hang there indefinitely.

### Freezes are reported to us

If the interface does not respond for more than eight seconds, AeroACARS writes this to its diagnostic log. If you have agreed to error reporting, a short report is also sent to us. That way we find such cases even when nobody reports them.

### Note for VA operators

The client needs no server change (`aeroacars-live`).
