## 🇩🇪 Deutsch

Härtungs-Runde nach der ausführlichen Qualitätssicherung vom 09.08.: der
Panel-Server für das In-Sim-HUD kann die App jetzt nachweislich nicht mehr
durch fehlerhafte Klienten belasten, und er ist für den Absturz-A/B-Test
abschaltbar.

### Neuer Schalter: Einstellungen > MSFS-In-Sim-HUD

Der Panel-Server (Port 47847) lässt sich abschalten. Standard: an; wirkt beim
nächsten Start von AeroACARS. Der Schalter ist primär ein Diagnose-Werkzeug:
die Beta-Abstürze sind weiterhin ungeklärt, und damit lässt sich prüfen, ob
sie auch OHNE Panel-Server auftreten — ohne auf v1.4.7 zurückzugehen. Ohne
Server zeigt das HUD im Sim dauerhaft "Keine Verbindung", alles andere läuft
normal.

### Panel-Server gegen fehlerhafte Klienten gehärtet

Der Feldtest zeigte fünf gleichzeitig offene, tote Verbindungen aus dem
Simulator (Verbindungsvorrat des eingebetteten Renderers plus Alt-Kopien des
Widgets). Nach dem Vorbild des LAN-Servers gilt jetzt:

- **Obergrenze von 8 gleichzeitigen Verbindungen** pro Adresse — Überzählige
  warten im TCP-Rückstau des Betriebssystems statt Ressourcen zu binden.
- **Lebenszeit-Schranke von 120 Sekunden pro Verbindung**: danach wird sie
  zwischen zwei Anfragen sauber geschlossen. Tote Steckplätze räumen sich
  damit garantiert selbst auf statt bis zum Sim-Neustart zu liegen; das
  Widget verbindet transparent neu.
- **WebSocket-Route entfernt.** Das Widget nutzt seit v1.2 reines Abfragen;
  die einzigen WS-Klienten wären Alt-Kopien, deren halbfertige Upgrades
  Aufgaben liegen ließen.

Beides ist mit echten Sockel-Tests abgesichert (EOF zum Stichtag,
Deckel am accept), nicht nur behauptet.

### Widget v3.0 (separat, im Tauschordner)

Das Flow-Widget wurde nach Abgleich mit der offiziellen parallel42-Doku neu
geschrieben: es nutzt jetzt den dokumentierten Lebenszyklus (`loop_1hz`,
`exit`, `html_created`) statt eigener setInterval-Schleifen. `exit` ist Flows
offizieller Aufräum-Haken vor jedem Neuladen — genau das Fehlen dieser
Registrierung war die Wurzel des "Zombie-Kopien"-Problems (Anzeige sprang
zwischen Fassungen, Verbindungsplätze verstopft). Braucht keine bestimmte
AeroACARS-Version.

### Zum Absturz

Weiterhin ungeklärt. Neu abgeglichen: es existiert eine bekannte
Heap-Korruptions-Fehlerklasse in Tauri/WebView2 auf Windows (Ereignis
`0xC0000374`, tauri-apps/tauri#12852) — die Bibliotheksversionen sind
zwischen v1.4.7 und den Betas allerdings identisch, ein Upstream-Update
scheidet als Erklärung aus. Der neue Schalter liefert den sauberen A/B-Test;
für den Beweis braucht es weiterhin ein Speicherabbild
(`LocalDumps`-Registrierung, siehe Anleitung im Tauschordner).

### Für VA-Betreiber

Keine Änderung am Datenformat zum Server. `aeroacars-live` muss nicht
mit-deployed werden.

## 🇬🇧 English

Hardening round following the extensive QA pass of Aug 09: the in-sim HUD's
panel server can demonstrably no longer be stressed by misbehaving clients,
and it can be disabled for the crash A/B test.

### New switch: Settings > MSFS in-sim HUD

The panel server (port 47847) can be turned off. Default: on; takes effect on
the next AeroACARS start. Primarily a diagnostic tool: the beta crashes remain
unexplained, and this allows checking whether they also occur WITHOUT the
panel server — without going back to v1.4.7. With the server off the in-sim
HUD permanently shows "no connection"; everything else runs normally.

### Panel server hardened against misbehaving clients

The field test showed five simultaneously open dead connections from the
simulator (the embedded renderer's connection pool plus old widget copies).
Following the LAN server's example:

- **Cap of 8 concurrent connections** per address — excess waits in the OS
  TCP backlog instead of binding resources.
- **Per-connection lifetime of 120 seconds**: afterwards the connection is
  closed cleanly between two requests. Dead slots are now guaranteed to clean
  themselves up instead of lingering until a sim restart; the widget
  reconnects transparently.
- **WebSocket route removed.** The widget has used plain polling since v1.2;
  the only WS clients would be old copies whose half-finished upgrades left
  tasks behind.

Both are backed by real socket tests (EOF at the deadline, cap at accept),
not just claimed.

### Widget v3.0 (separate, in the transfer folder)

The Flow widget was rewritten after comparing against the official parallel42
documentation: it now uses the documented lifecycle (`loop_1hz`, `exit`,
`html_created`) instead of home-grown setInterval loops. `exit` is Flow's
official cleanup hook before every reload — the absence of exactly this
registration was the root of the "zombie copies" problem. Works with any
AeroACARS version.

### On the crash

Still unexplained. Newly cross-checked: a known heap-corruption bug class
exists in Tauri/WebView2 on Windows (event `0xC0000374`,
tauri-apps/tauri#12852) — however, dependency versions are identical between
v1.4.7 and the betas, so an upstream update is ruled out as the explanation.
The new switch provides the clean A/B test; proof still requires a crash dump
(`LocalDumps` registration, see the guide in the transfer folder).

### For VA operators

No wire-format change. `aeroacars-live` does not need to be deployed
alongside this build.
