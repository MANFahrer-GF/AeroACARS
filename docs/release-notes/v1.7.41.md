## 🇩🇪 Deutsch

### Die Verbindung reißt nicht mehr im Minutentakt — und die Sprit-Tabelle sagt, was sie meint

**Der wichtigste Punkt zuerst:** Bei mehreren Piloten riss die Verbindung zum Live-Server etwa jede Minute ab. Ursache war eine liegengebliebene Bahnkorrektur, die ein paar hundert Byte zu groß war: Der Client konnte sie nicht senden, warf deswegen die ganze Verbindung weg, baute neu auf — und versuchte es eine Minute später erneut. Über 600 Mal an einem Tag. Wer in so einem Moment aufsetzte, dessen Landung kam nie beim Server an; der Flug landete dann in der Prüfliste, obwohl alles in Ordnung war.

- **Die Größe stimmt jetzt.** Der Client darf so große Nachrichten senden, wie der Server sie annimmt.
- **Eine zu große Nachricht kostet nie wieder die Verbindung.** Sie fällt aus, die Leitung bleibt stehen.
- **Alte Rückstände räumt der Client beim Start selbst auf.** Niemand muss Dateien löschen. Liegengebliebene Korrekturen gehen danach raus und verschwinden.
- **Die Landung wird bestätigt.** Kommt sie nicht an, schickt der Client sie beim Einreichen erneut. Klappt auch das nicht, steht es im Fenster — statt stillschweigend eine Bewertung anzuzeigen, die der Server nie bekommen hat.

### Sprit Wegpunkt für Wegpunkt: Verbrauch statt Tankstand

- **Die Spalte rechnet jetzt den echten Verbrauch.** Vorher verglich sie Tankstände. Wer mehr getankt hatte als geplant, bekam dauerhaft „weniger verbraucht" zu sehen, während die Ampel rot war — Text und Farbe widersprachen sich.
- **Die Abflugzeile sagt, was sie meint:** „X kg mehr getankt als geplant". Beim Abheben ist noch nichts verbraucht.
- **Keine roten Zeilen mehr aus dem Startschub.** Die Hochrechnung auf die Landung beginnt erst, wenn genug Strecke gemessen ist. Vorher wurden aus drei Minuten Steigflug Alarmwerte, die sich ab dem vierten Wegpunkt von selbst erledigten.

### Fehlersuche ohne Nachfragen

- **Das Diagnose-Protokoll des Clients reist mit dem Flugprotokoll mit.** Bei dem Verbindungsfehler oben stand die entscheidende Zeile ausschließlich auf dem Rechner des Piloten; die Suche dauerte deshalb zwei Tage. Künftig liegt sie beim Flugbericht. Es enthält keine Zugangsdaten und ist gepackt wenige Dutzend Kilobyte groß.

**Für VA-Betreiber:** Die Live-Übersicht (aeroacars-live) wurde mit diesem Release aktualisiert und nimmt das Diagnose-Protokoll entgegen. Ohne diese Aktualisierung funktioniert der Client normal weiter, nur der Upload des Protokolls schlägt fehl (ohne Folgen für den Flug).

## 🇬🇧 English

### No more connection drops every minute — and the fuel table says what it means

**The important one first:** for several pilots the connection to the live server dropped about once a minute. The cause was a leftover runway correction that was a few hundred bytes too large: the client could not send it, threw away the whole connection because of it, reconnected — and tried again a minute later. More than 600 times in a single day. Anyone touching down in such a moment had their landing never reach the server; the flight then ended up in the review list although everything was fine.

- **The size limit is right now.** The client may send messages as large as the server accepts.
- **An oversized message never costs the connection again.** It is dropped, the line stays up.
- **The client clears old leftovers at startup.** Nobody has to delete files. Stranded corrections go out afterwards and disappear.
- **The landing is acknowledged.** If it does not arrive, the client sends it again when filing. If that fails too, it says so in the window — instead of quietly showing a score the server never received.

### Fuel waypoint by waypoint: burn, not tank level

- **The column now shows the actual burn.** Before, it compared tank levels. If you had more fuel on board than planned, it permanently read "less burnt" while the traffic light was red — text and colour contradicted each other.
- **The departure row says what it means:** "X kg more fuel than planned". Nothing is burnt at lift-off.
- **No more red rows from take-off thrust.** The projection to landing only starts once enough distance has been measured. Before, three minutes of climb produced alarming numbers that sorted themselves out by the fourth waypoint.

### Troubleshooting without asking around

- **The client's diagnostic log travels with the flight log.** For the connection bug above, the decisive line existed only on the pilot's machine, which is why the hunt took two days. From now on it sits next to the flight report. It contains no credentials and is a few dozen kilobytes compressed.

**For VA operators:** the live overview (aeroacars-live) has been updated with this release and accepts the diagnostic log. Without that update the client works as usual; only the log upload fails, with no consequences for the flight.
