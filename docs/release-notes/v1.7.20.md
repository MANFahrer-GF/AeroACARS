## 🇩🇪 Deutsch

### CPDLC/PDC: Sitzungsende zuverlässiger

Bei einer Verbindung, die während des Fluges die Station gewechselt hat, konnte es passieren, dass eine bereits beendete Sitzung intern nicht sauber abgeschlossen wurde — eine alte, unbeantwortete Nachricht der vorherigen Station blieb dann als "offen" stehen, obwohl längst zur nächsten Station gewechselt wurde. Das betraf sowohl das manuelle Abmelden als auch den automatischen Stationswechsel. Die Sitzungsverwaltung wurde von Grund auf neu gebaut: Station und Sitzungszustand hängen jetzt an einer einzigen, konsistenten Stelle statt an mehreren getrennten Feldern, die zu unterschiedlichen Zeitpunkten aktualisiert wurden.

Im Zuge dieser Arbeit wurde zusätzlich eine Absicherung nachgezogen: eine Nachricht wird jetzt nur noch dann als "Antwort auf unsere Logon-Anfrage" behandelt, wenn sie wirklich von der angefragten Station stammt — nicht mehr allein anhand einer mitgeschickten Nummer, die theoretisch auch von einer anderen Quelle stammen könnte.

### CPDLC/PDC: Reiter öffnet jetzt den richtigen Modus

Der CPDLC/PDC-Menüpunkt in der Seitenleiste öffnete bisher unabhängig vom Kontext immer den PDC-Unterreiter — auch mitten im Flug, wo PDC (Pre-Departure Clearance) keine Bedeutung mehr hat. Jetzt öffnet der Reiter automatisch CPDLC, sobald das Flugzeug nicht mehr am Boden vor dem Start steht; nur vor dem Start (Preflight/Boarding/Pushback/Rollen zur Bahn) bleibt PDC der sinnvolle Standard. Wartet eine unbeantwortete CPDLC-Nachricht auf Antwort, öffnet der Reiter ohnehin direkt CPDLC.

### Landeauswertung: Ausroll-Feinwerte gehen nach einer Verbindungslücke nicht mehr verloren

Wenn deine Verbindung während des Fluges kurz abriss und dein Flug deshalb erst im Nachhinein automatisch nachgeliefert wurde (statt live übertragen zu werden), fehlten in der Landeauswertung bisher die Ausroll-Feinwerte — wo genau du die Bahn verlassen hast, ab wann nicht mehr gewertet wurde, auf welcher Seite du abgebogen bist. Der Client zeichnet diese Werte jetzt zusätzlich lokal in deinem Flugprotokoll auf, sodass sie bei einer nachträglichen Übertragung nicht mehr verloren gehen. **Sichtbar wird das erst, sobald die passende Serverseite live ist** — siehe unten.

### Was das für dich bedeutet

- Ein Stationswechsel oder eine manuelle Abmeldung hinterlässt keine "hängenden" alten Nachrichten mehr, die fälschlich als offen angezeigt werden.
- Der CPDLC/PDC-Reiter zeigt dir künftig direkt das, was in deiner aktuellen Flugphase relevant ist, statt jedes Mal manuell umschalten zu müssen.
- Landungen, die nach einer Verbindungslücke automatisch nachgeliefert werden, verlieren ihre Ausroll-Details nicht mehr (Wirkung folgt mit dem Server-Update).

## 🇬🇧 English

### CPDLC/PDC: session end made more reliable

When a connection changed stations mid-flight, the previous session could sometimes fail to close cleanly internally — an old, unanswered message from the previous station could then be left showing as "still open" even though the aircraft had already moved on to the next station. This affected both manual logoff and automatic station handover. Session management was rebuilt from the ground up: station and session state now live in one consistent place instead of several separate fields updated at different times.

Alongside this, a hardening fix was carried through: a message is now only treated as "the reply to our logon request" when it genuinely comes from the station we asked — not solely based on an accompanying number that could in principle have come from elsewhere.

### CPDLC/PDC: tab now opens the right mode

The CPDLC/PDC menu item in the sidebar used to always open the PDC sub-tab regardless of context — even mid-flight, where PDC (Pre-Departure Clearance) no longer applies. It now opens CPDLC automatically once the aircraft is no longer on the ground before departure; only before departure (preflight/boarding/pushback/taxiing to the runway) does PDC remain the sensible default. If an unanswered CPDLC message is waiting for a reply, the tab opens straight to CPDLC regardless.

### Landing evaluation: rollout details no longer lost after a connectivity gap

If your connection briefly dropped mid-flight and your flight was therefore recovered automatically afterwards instead of streaming live, the landing evaluation was missing the rollout details — exactly where you left the runway, from where scoring stopped counting, which side you exited on. The client now additionally records these values locally in your flight log, so they survive a delayed upload. **This only becomes visible once the matching server update is live** — see below.

### What this means for you

- A station handover or manual logoff no longer leaves "stuck" old messages incorrectly shown as open.
- The CPDLC/PDC tab now shows you what's actually relevant for your current flight phase, instead of needing a manual switch every time.
- Landings recovered after a connectivity gap no longer lose their rollout details (effect lands with the server update).

### Für VA-Betreiber / For VA operators

Der Client-Teil des Ausroll-Fixes ist **bereits in diesem Release (v1.7.20) enthalten** — Piloten mit dem aktuellen Client zeichnen die Werte ab sofort lokal auf. Sichtbar in der Live-Webapp wird das aber erst, sobald `aeroacars-live` (der Recorder auf live.kant.ovh) die passende Gegenseite bekommt, die dieses neue Ereignis beim Gap-Fill-Import auch verarbeitet — diese Korrektur ist bereits umgesetzt, wird aber **separat auf dem Server deployed**.

The client half of the rollout fix is **already included in this release (v1.7.20)** — pilots on the current client record these values locally starting now. It only becomes visible in the live webapp once `aeroacars-live` (the recorder on live.kant.ovh) gets the matching counterpart that processes this new event during gap-fill import — that fix has already been implemented but is **deployed on the server separately**.
