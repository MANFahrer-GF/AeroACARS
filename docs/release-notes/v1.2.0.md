# v1.2.0 — Ehrlichere Landebewertung bei Sim-/App-Abstürzen

## 🇩🇪 Deutsch

**Zwei Dinge in diesem Release, beide rund um denselben Fall: der Sim oder AeroACARS selbst bricht mitten im Flug ab.**

**1. Keine erfundenen Landewerte mehr, wenn nie wirklich gelandet wurde.**
Bisher konnte es passieren, dass ein Flug, bei dem AeroACARS aus irgendeinem Grund nie eine echte Sinkrate am Touchdown erfassen konnte (z. B. weil der Sim oder die App mitten im Endanflug abgestürzt ist), trotzdem als "butterweiche Landung" mit vollen Punkten gewertet wurde — weil intern ein Platzhalterwert (0 fpm) genau wie eine echte Messung behandelt wurde. Das ist jetzt behoben: fehlt eine echte Messung, wird die betroffene Achse (Sinkrate, G-Kraft) ehrlich als "nicht gemessen" markiert statt eine Zahl zu erfinden — sowohl im Score als auch im Freitext des Flugberichts.

**2. AeroACARS erkennt jetzt, wenn der Sim oder die App selbst abgestürzt ist.**
Bricht die Telemetrie ab, prüft AeroACARS jetzt zusätzlich (plattformübergreifend, Windows/Mac/Linux):
- Läuft der Simulator-Prozess (MSFS/X-Plane) überhaupt noch, oder ist er weg?
- Ist AeroACARS selbst beim letzten Mal sauber beendet worden, oder abgestürzt/gekillt worden?
- Gab es beim Wiederaufsetzen einen physikalisch unmöglichen Sprung (z. B. Tank füllt sich von selbst mitten im Flug)?

Diese Zusatz-Infos werden — nur wenn tatsächlich etwas Auffälliges passiert ist — an den VA-Betreiber übermittelt, damit ein manuell zu prüfender Flug nicht mehr blind dasteht ("warum ist der eigentlich hängengeblieben?"), sondern sofort die wahrscheinliche Ursache zeigt.

**Für den ganz normalen Flug ändert sich nichts** — beide Punkte greifen nur in den seltenen Fällen, in denen vorher sowieso etwas schiefgelaufen ist. Kein neuer Klick, kein neues Setting.

Auf VA-Seite (German Sky Group) ist die Server-Seite bereits live — kein weiterer Schritt nötig.

## 🇬🇧 English

**Two things in this release, both about the same underlying case: the sim or AeroACARS itself dies mid-flight.**

**1. No more fabricated landing numbers when there was never a real landing.**
Previously, a flight where AeroACARS could never capture a genuine touchdown sink rate (e.g. because the sim or the app crashed during final approach) could still score a "perfect greaser landing" with full points — because internally, a placeholder value (0 fpm) was treated exactly like a real measurement. That's fixed now: when there's no real measurement, the affected axis (landing rate, G-force) is honestly marked "not measured" instead of showing a made-up number — both in the score and in the PIREP's plain-text summary.

**2. AeroACARS now detects when the sim or the app itself crashed.**
When telemetry drops, AeroACARS now additionally checks (cross-platform, Windows/Mac/Linux):
- Is the simulator process (MSFS/X-Plane) still running, or is it gone?
- Did the previous AeroACARS run exit cleanly, or did it crash/get killed?
- Was there a physically impossible jump on resume (e.g. the fuel tank refilling itself mid-flight)?

This extra context is sent to the VA owner — only when something actually looks off — so a flight flagged for manual review no longer sits there unexplained; the likely cause is right there.

**Nothing changes for a normal flight** — both points only kick in for the rare cases where something already went wrong. No new click, no new setting.

On the VA side (German Sky Group), the server-side piece is already live — no further action needed.
