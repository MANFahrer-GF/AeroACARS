## 🇩🇪 Deutsch

Diese Version behebt eine falsch gezählte Strecke bei Zeitraffer und zeigt dir an, wenn die Simulationsrate nicht auf 1× steht.

### Strecke bei Zeitraffer wird richtig gezählt

Wer im Simulator den Zeitraffer benutzt (2×, 4×, 8× oder 16×), bekam bisher eine zu kurze Strecke ins Logbuch. AeroACARS hielt die Teilstücke für unmöglich schnell und lehnte sie ab, weil es die Geschwindigkeit in echter Uhrzeit gemessen hat, nicht in Simulationszeit. In einem Flug mit zeitweise 8× blieben so rund 40 % der Strecke ungezählt; die Flugzeit war dagegen richtig. Jetzt wird die erlaubte Strecke aus Groundspeed und Simulationsrate berechnet. Eine Obergrenze verhindert, dass große Sprünge quer über die Weltkarte (Teleport, Karte neu laden) als Flug gezählt werden; bei 16× und üblicher Reisegeschwindigkeit sind das knapp 360 Seemeilen je Messlücke, kleinere Sprünge können bei hoher Rate also mitgezählt werden. Raten über 16× (MSFS kennt bis 128×) werden weiterhin nicht mitgezählt.

Bereits abgegebene Flüge werden nicht neu gerechnet.

### Hinweis im Cockpit, wenn die Simulationsrate nicht 1× ist

Steht die Simulationsrate länger als zwei Minuten nicht auf 1×, zeigt das Cockpit jetzt einen gelben Hinweis. Das gilt in beide Richtungen, auch bei 0,25× oder 0,5×. Der Hinweis dient nur der Anzeige, er ändert nichts an der Wertung. Er soll auffallen, wenn eine Taste versehentlich verrutscht ist, bevor daraus Stunden werden.

### Neue Diagnose beim Programmstart

AeroACARS schreibt beim Start eine Zeile ins technische Log: Version der Anzeigekomponente (WebView2), Zahl der laufenden WebView2- und weiterer AeroACARS-Prozesse und ob der Datenordner der Anzeigekomponente schon existiert. Anlass: Bei einem neuen Piloten ließ sich das Hauptfenster beim ersten Start mehrfach nicht anlegen. Die Zeile ändert nichts am Verhalten, sie hilft nur, solche Fälle künftig einzuordnen.

### Hinweis für VA-Betreiber

Der Client braucht keine Server-Änderung (`aeroacars-live`).

## 🇬🇧 English

This version fixes a distance undercount during time acceleration and shows a notice when the simulation rate is not 1×.

### Distance is counted correctly during time acceleration

Pilots who used the simulator's time acceleration (2×, 4×, 8× or 16×) got a distance in the logbook that was too short. AeroACARS considered the segments impossibly fast and rejected them, because it measured speed against real clock time rather than simulation time. In a flight with stretches at 8×, about 40 % of the distance went uncounted; the flight time was correct. The permitted distance is now derived from ground speed and simulation rate. An upper limit prevents large jumps across the world map (teleport, map reload) from being counted as flight; at 16× and typical cruise speed that is just under 360 nautical miles per measurement gap, so smaller jumps can still be counted at a high rate. Rates above 16× (MSFS goes up to 128×) are still not counted.

Flights that were already filed are not recalculated.

### Cockpit notice when the simulation rate is not 1×

If the simulation rate stays away from 1× for more than two minutes, the cockpit now shows a yellow notice. This applies in both directions, including 0.25× or 0.5×. The notice is display only and does not change the score. It is meant to catch a key pressed by accident before it turns into hours.

### New diagnostics at program start

At start AeroACARS writes one line to the technical log: the version of the display component (WebView2), the number of running WebView2 and other AeroACARS processes, and whether the display component's data folder already exists. Reason: for a new pilot the main window could not be created several times on the first start. The line changes no behaviour; it only helps to classify such cases in future.

### Note for VA operators

The client needs no server change (`aeroacars-live`).
