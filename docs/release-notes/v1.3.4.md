## 🇩🇪 Deutsch

### Fix: Reihenfolge von CPDLC-Nachrichten beim Anmelden konnte unlogisch wirken

Wenn beim Anmelden bei einer neuen Station mehrere Nachrichten gleichzeitig ankamen (z. B. "LOGON ACCEPTED", eine Anweisung wie "PROCEED DIRECT TO ...", und "CURRENT ATC UNIT ..."), zeigte das CPDLC-Log sie exakt in der Reihenfolge, in der die Bodenstation sie verschickt hat. Das ist protokoll-technisch korrekt, konnte aber verwirrend wirken, wenn eine Anweisung angezeigt wurde, bevor klar war, mit welcher Station man überhaupt verbunden ist.

Nachrichten, die im selben Abrufzyklus ankommen, werden jetzt so sortiert: reine Info-Meldungen ohne Antwortpflicht (LOGON ACCEPTED, CURRENT ATC UNIT) erscheinen vor Anweisungen, die eine Antwort verlangen (z. B. PROCEED DIRECT TO). Die WILCO-Antwort bleibt dabei technisch korrekt mit ihrer Anweisung verknüpft — es ändert sich nur die Anzeige-Reihenfolge. Nachrichten, die zu unterschiedlichen Zeiten ankommen, bleiben unverändert in ihrer echten Reihenfolge. Enthält ein Abruf eine Telex-Nachricht, ein nicht dekodierbares Paket oder eine Sektorübergabe, wird gar nicht umsortiert — dort bleibt alles exakt so, wie es ankam.

### Hinweis

Reines Client-Update — aktualisiert sich automatisch.

## 🇬🇧 English

### Fix: CPDLC message order on logon could read as backwards

When logging on to a new station, several messages sometimes arrived together (e.g. "LOGON ACCEPTED", an instruction like "PROCEED DIRECT TO ...", and "CURRENT ATC UNIT ..."). The CPDLC log showed them in the exact order the ground station sent them — correct on the wire, but confusing when an instruction appeared before it was clear which station had even issued it.

Messages arriving in the same poll cycle are now sorted so that purely informational messages with no reply owed (LOGON ACCEPTED, CURRENT ATC UNIT) show before instructions that need a reply (e.g. PROCEED DIRECT TO). The WILCO reply stays correctly linked to its instruction underneath — only the display order changes. Messages arriving at genuinely different times are left in their true arrival order as before. If a batch contains a telex message, an undecodable packet, or a sector handover, no reordering happens at all — everything stays exactly as received.

### Note

Pure client update — auto-updates.
