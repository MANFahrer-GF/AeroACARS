## 🇩🇪 Deutsch

### Absturz-Ursachensuche

Die Betas 1 und 2 sind bei einem Piloten dreimal an einem Vormittag abgestürzt,
v1.4.7 dagegen nicht. Die Windows-Ereignisanzeige nannte `0xC0000374`
(Heap-Korruption) und `0xC000001D` (ungültiger Befehl). Eine Qualitätssicherung
über den gesamten Unterschied seit v1.4.7 hat einen starken Kandidaten gefunden.

**Panel-Server fährt beim Beenden geordnet herunter.** Er war die einzige
langlebige Aufgabe der App ohne jeden Stopp-Weg — MQTT, Hoppie, der
LAN-Fernzugriff-Server und der Positions-Streamer haben alle einen. Er hielt
einen App-Zeiger und griff im Sekundentakt auf den Zustandsspeicher zu, während
die App abgebaut wurde. Ein Zugriff auf bereits freigegebenen Speicher zeigt
sich genau als die beiden obigen Fehlercodes.

Das ist eine begründete Vermutung, kein Beweis — den liefert erst ein
Speicherabbild. Der fehlende Stopp-Weg war unabhängig davon ein Defekt.

**Neu: Logdatei.** Bis hierher schrieb AeroACARS ausschließlich nach stdout,
was beim Start aus dem Explorer ins Leere läuft — drei Abstürze hinterließen
deshalb keine einzige Zeile. Es gibt jetzt eine täglich rotierende Logdatei
unter `%APPDATA%\com.aeroacars.app\logs`, sieben Tage werden aufgehoben. Jede
Zeile wird sofort geschrieben und nicht gepuffert, damit gerade die letzten
Zeilen vor einem Absturz erhalten bleiben. Rust-Abstürze im Programminneren
landen zusätzlich dort.

### MSFS-In-Sim-HUD

- **Neue Werte für die Anzeige im Simulator:** Höhe über Grund, Gegen- und
  Seitenwind auf die Flugzeugachsen gedreht, sowie der Tankinhalt. Die
  Vorzeichen des Windes entsprechen exakt denen im Landeprotokoll, damit
  Anflug und Ergebnis nicht unterschiedlich rechnen.
- **Neue Route für den Aktivitäts-Ticker:** `GET /panel/activity`. Nur über
  127.0.0.1 erreichbar, wie die drei bestehenden Panel-Routen.
- **Landebahn im Anflug wird geschätzt.** MSFS liefert die von der Flugsicherung
  gewählte Bahn nicht — ein Datenaudit fand das Feld bei 407 von 407
  ausgewerteten Flügen leer. Die Schätzung kommt aus Position und Steuerkurs
  gegen die Navigationsdaten und trennt Parallelbahnen über den Abstand zur
  Mittellinie. Sie fließt **nicht** in den PIREP: dort bleibt der genauere
  Abgleich nach dem Aufsetzen die Quelle.

### Für VA-Betreiber

Keine Änderung am Datenformat zum Server. `aeroacars-live` muss **nicht**
mit-deployed werden.

## 🇬🇧 English

### Crash investigation

Betas 1 and 2 crashed three times in one morning for one pilot, while v1.4.7
did not. The Windows Event Log reported `0xC0000374` (heap corruption) and
`0xC000001D` (illegal instruction). A QA pass over the complete diff since
v1.4.7 found a strong candidate.

**The panel server now shuts down cleanly.** It was the only long-lived task in
the app without any stop path — MQTT, Hoppie, the LAN remote-control server and
the position streamer all have one. It held an app handle and reached into the
state store once per second while the app was being torn down. Reading memory
that has already been freed surfaces as exactly the two error codes above.

This is a reasoned hypothesis, not proof; only a crash dump can confirm it. The
missing stop path was a defect regardless.

**New: a log file.** Until now AeroACARS logged to stdout only, which goes
nowhere when the app is launched from Explorer — which is why three crashes left
no trace at all. There is now a daily-rotating log file under
`%APPDATA%\com.aeroacars.app\logs`, keeping seven days. Every line is written
through immediately rather than buffered, so the lines right before a crash
survive. Rust panics are routed there as well.

### MSFS in-sim HUD

- **New values for the in-sim display:** height above ground, headwind and
  crosswind rotated onto the aircraft axes, and fuel on board. The wind sign
  convention matches the landing record exactly, so the approach and the result
  never disagree.
- **New route for the activity ticker:** `GET /panel/activity`. Loopback-only,
  like the three existing panel routes.
- **The landing runway is now predicted during the approach.** MSFS does not
  supply the ATC-selected runway — a data audit found the field empty on 407 of
  407 flights. The prediction comes from position and heading matched against
  the navigation data, and separates parallel runways by centreline offset. It
  deliberately does **not** feed the PIREP: the post-touchdown correlation
  remains the source there.

### For VA operators

No wire-format change. `aeroacars-live` does **not** need to be deployed
alongside this build.
