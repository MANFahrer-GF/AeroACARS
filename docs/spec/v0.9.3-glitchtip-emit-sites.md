**Status:** DRAFT R1 — addresses QS-R0 findings (1 P0, 5 P1, 2 P2)

## Ziel

Pilot-Client v0.9.3 sendet bei den 9 wichtigsten User-impacting Fehler-Klassen ein anonymisiertes Custom-Event an `tip.kant.ovh`. Damit:

1. **VA-Owner sieht Bugs bevor Piloten sie melden** (Adrian/Svenny-Pattern wäre in ≤15 min sichtbar gewesen).
2. **GlitchTip-Investition (v0.9.0/v0.9.1/v0.9.2 Plumbing) wird produktiv** — nicht nur Theorie.
3. **Keine Privacy-Regression** — Allowlist + Redaction aus v0.9.0 bleibt hart durchgesetzt.
4. **Keine Quota-Explosion** — Rate-Limiting verhindert dass MQTT-Reconnect-Loops oder ähnliche „Storm"-Pattern das Daily-Quota in 30 Sekunden verbrennen.

## Leitentscheidungen

### LE1 — Site-Liste pragmatisch auf 9 Pilot-Client-Sites

Aus den 11 Sites der v0.9.0-Spec wählen wir **9 die heute funktional emittierbar sind** und für jede `error.code` definiert ist. Eine Site (`Forensic-only Bounce`) wird zurückgestellt weil sie für die Top-Pain-Points (Pilot kann nicht updaten, Pilot bekommt falschen Score, PIREP kommt nicht durch) nicht relevant ist — kann in v0.9.4 nachgereicht werden.

Plus eine Site **NEU** die in v0.9.0-Spec fehlte aber Adrian-Pattern relevant ist: **Auto-Update-Check-Fail**.

| # | Site | Severity | Trigger | error.code |
|---|---|---|---|---|
| S1 | PIREP-Submit-Fail transient | Warn | HTTP 5xx oder Network-Timeout im `file_pirep_with_retry`-Loop, NACH 3 Versuchen scheitert | `pirep_file_failed_transient` |
| S2 | PIREP-Submit-Fail hard | Error | HTTP 4xx ohne Retry (validation/auth), oder Final-Failure in Background-Worker | `pirep_file_failed_hard` |
| S3 | SimConnect-Disconnect | Info | Pipe-Break / Reconnect-Loop-Start (= einmal pro Loop, NICHT pro Retry-Versuch) | `sim_disconnect` |
| S4 | Aircraft-Mismatch | Warn | Pilot startet Flug mit anderem Aircraft als gebid (vor Acknowledge) | `aircraft_mismatch` |
| S5 | not_at_departure | Warn | Pilot drückt Auto-Start, ist aber > 5 nm vom planned dep entfernt | `not_at_departure` |
| S6 | Hard Landing | Warn | V/S ≤ -600 fpm oder Peak-G ≥ 1.70 bei Touchdown | `hard_landing` |
| S7 | Auto-Update-Check-Fail | Info | Tauri-Updater HTTP-Fehler beim `latest.json`-Fetch (Network/4xx/5xx) | `update_check_failed` |

**Reihenfolge der Implementation:** S1 → S2 → S3 → … → S9, in genau dieser Order. Jede Site ein atomarer Commit (Code + Test + Doc-Eintrag), jeder Commit live gegen tip.kant.ovh verifizierbar bevor der nächste startet.

### LE2 — Rate-Limiting: Token-Bucket pro `error.code`

**Problem:** ohne Limit könnte ein MQTT-Reconnect-Storm 100×/s `S8` triggern → Daily-Quota leer + tip.kant.ovh-Dashboard unbedienbar.

**Lösung:** zentraler Token-Bucket pro `error.code`-String. Default-Config:

```rust
// in client/src-tauri/src/sentry_init.rs (NEU)
const RATE_LIMIT_DEFAULTS: &[(&str, RateLimit)] = &[
    // (error.code, RateLimit { max_per_window, window_seconds })
    ("pirep_file_failed_transient", RateLimit { max: 3, secs: 300 }),   // 3 / 5min
    ("pirep_file_failed_hard",      RateLimit { max: 5, secs: 60 }),    // 5 / min (hart wollen wir sehen)
    ("sim_disconnect",              RateLimit { max: 1, secs: 60 }),    // 1 / min (Reconnect-Loops koalesziert)
    ("aircraft_mismatch",           RateLimit { max: 5, secs: 60 }),
    ("not_at_departure",            RateLimit { max: 5, secs: 60 }),
    ("hard_landing",                RateLimit { max: 10, secs: 60 }),
    ("update_check_failed",         RateLimit { max: 1, secs: 600 }),   // 1 / 10min (laufender Check)
    ("recorder_upload_failed",      RateLimit { max: 3, secs: 60 }),
    ("dds_violation",               RateLimit { max: 10, secs: 60 }),
];

// Fallback wenn error.code nicht in Liste: max=10, secs=60
```

**Implementierung:** `HashMap<String, BucketState>` mit `BucketState { tokens_remaining, window_started_at }`. Vor `capture_message`-Call: `try_consume_token(error_code)`. Wenn `false` returnt → Event verwerfen + `tracing::debug!` loggen. Wenn `true` → durchsenden.

**Sentry-SDK eigene Rate-Limits** bleiben unverändert (HTTP 429-Response respektieren). Unser Token-Bucket ist eine ZUSÄTZLICHE Defense.

### LE3 — Aufrufer-Pattern: Function `emit()` + Tag-Key-Konstanten

**R1-Fix P0 (R0-Macro war kaputt):** Das ursprüngliche R0 nutzte `macro_rules! report_event!` mit `$tag_key:ident` + `stringify!($tag_key)`. Problem: Rust-Identifier dürfen keinen Punkt enthalten, also musste das Macro `error_kind` / `pirep_id` als Identifier nehmen → `stringify!` produzierte den String `"error_kind"`. Die Allowlist im `sentry_init.rs:57` erwartet aber `"error.kind"`, `"pirep.id"`. Konsequenz: `before_send` hätte ALLE Diagnose-Tags wieder rausgestrippt (Privacy-Allowlist greift gegen unsere eigenen Tags).

**Lösung R1:** kein Macro. Stattdessen normale Function mit slice-arg + **typed tag-key constants** die compile-time bindlich sind:

```rust
// in client/src-tauri/src/sentry_init.rs (NEU, Submodul tag_keys)
pub mod tag_keys {
    //! Die einzigen Tag-Keys die `emit()` akzeptiert. Identisch zur
    //! Allowlist in `allowed_tag_keys()` — wer hier eine Konstante
    //! ergaenzt MUSS auch die Allowlist erweitern (= 2-Stellen-
    //! Bewusstseinszwang dass dieser neue Tag privacy-konform ist).
    pub const ERROR_CODE: &str = "error.code";
    pub const ERROR_KIND: &str = "error.kind";
    pub const ERROR_STATUS_CODE: &str = "error.status_code";
    pub const SIMULATOR: &str = "simulator";
    pub const AIRCRAFT: &str = "aircraft";
    pub const AIRPORT: &str = "airport";
    pub const RUNWAY: &str = "runway";
    pub const PIREP_ID: &str = "pirep.id";
    pub const CALLSIGN: &str = "callsign";
    pub const PHASE: &str = "phase";
    pub const FORENSICS_VERSION: &str = "forensics.version";
    pub const DISTANCE_BUCKET: &str = "distance.bucket";
    pub const FEATURE_FLAG: &str = "feature.flag";
    // `app.component`, `app.version`, `os`, `os.version`, `pilot.hash`
    // werden vom Init-Scope gesetzt, NICHT per emit().
}

/// Sentry-Event mit Rate-Limit + Allowlist + Fingerprint senden.
/// Returns `true` wenn Event an Transport übergeben, `false` wenn
/// verworfen (Consent aus / Rate-Limit / Sentry nicht init).
pub fn emit(
    level: sentry::Level,
    error_code: &'static str,
    message: &str,
    tags: &[(&'static str, String)],
) -> bool {
    // Consent-Gate
    if !CONSENT.load(Ordering::Relaxed) {
        return false;
    }
    // Rate-Limit-Gate (testbar via inject_clock-Variante, siehe LE4)
    if !try_consume_token(error_code, Instant::now()) {
        tracing::debug!(error_code, "[sentry] rate-limited — event dropped");
        return false;
    }
    // Send
    sentry::with_scope(
        |scope| {
            // P1-3-Fix: explizite Fingerprint-Gruppierung. Sentry/GlitchTip
            // gruppiert per Default nach message+stacktrace — wenn message
            // variiert (z.B. "PIREP file failed (transient — will retry)"
            // mit attempt-counter), entsteht pro Variation ein neuer Issue.
            // Mit fixem fingerprint ist `error.code` der echte Group-Key.
            scope.set_fingerprint(Some(["aeroacars", error_code].as_slice()));
            scope.set_tag(tag_keys::ERROR_CODE, error_code);
            for (k, v) in tags {
                scope.set_tag(*k, v);
            }
        },
        || {
            sentry::capture_message(message, level);
        },
    );
    true
}
```

Verwendung an Site (S1-Beispiel):

```rust
use crate::sentry_init::{emit, tag_keys};

sentry_init::emit(
    sentry::Level::Warning,
    "pirep_file_failed_transient",
    "PIREP file failed (transient — will retry)",
    &[
        (tag_keys::ERROR_KIND, kind.into()),
        (tag_keys::ERROR_STATUS_CODE, status),
        (tag_keys::PIREP_ID, pirep_id.clone()),
    ],
);
```

**Vorteile vs. ursprüngliches Macro:**
- Tag-Keys sind Compile-Time-Konstanten (`tag_keys::PIREP_ID`) → Tippfehler scheitern beim Compile, nicht erst im Privacy-Filter
- Allowlist und `tag_keys`-Modul sind 1:1 spiegelgleich → strukturelle Sicherheit
- Function statt Macro → trivial mockbar, kein `$crate::`-Magic
- `error.code` wird IMMER gesetzt (durch `emit()` selbst) — kein Aufrufer kann's vergessen
- Fingerprint ist explizit → group-Vertrag ist Code, nicht Sentry-Heuristik

### LE4 — Test-Strategie: 3-Schichten, alles privacy-konform

**R1-Fix P1-1 (R0-Tests waren nicht kompilierbar):** R0 hatte Tests in `client/src-tauri/tests/glitchtip_emit_sites.rs` (= externes integration-test-crate). Aber `sentry_init` ist in `lib.rs:17` als privates Modul deklariert, `CONSENT` ist private static, `allowed_tag_keys()` ist private fn. Externes crate sieht nichts davon → R0-Tests hätten gar nicht kompiliert.

**Lösung R1:** alle Tests als `#[cfg(test)] mod tests` IM jeweiligen Modul. Drei Schichten, gleiches privacy-Setup:

**Schicht 1 — Sentry-Mechanik-Tests** in `client/src-tauri/src/sentry_init.rs` als `#[cfg(test)] mod tests` ganz unten. Sieht alle privaten Items (`CONSENT`, `try_consume_token`, `RATE_LIMIT_DEFAULTS`). Testet:
- Token-Bucket-Verhalten (Verbrauch, Reset, unknown-Code-Default)
- Consent-Off verwirft ohne Token-Verbrauch
- `emit()` setzt `error.code` + fingerprint + Tags korrekt
- `before_send`/`redact_event` strippt nicht die in `emit()` gesetzten Tags

**P2-2-Fix Clock-Injection:** statt `Instant::now()` direkt nimmt `try_consume_token` ein `now: Instant`-Argument. In Production-`emit()` reicht der den `Instant::now()` durch. Im Test kann der Test einen manipulierten Instant + tiny `RateLimit { max: 2, secs: 1 }` injizieren → Test läuft in 1.1 sec statt 61 sec, ist deterministisch statt sleep-flaky.

```rust
// in sentry_init.rs
fn try_consume_token(error_code: &str, now: Instant) -> bool { ... }

pub fn emit(...) -> bool {
    // ...
    if !try_consume_token(error_code, Instant::now()) { return false; }
    // ...
}

#[cfg(test)]
mod tests {
    use super::*;
    use std::time::Duration;

    fn fresh_buckets() {
        BUCKETS.get_or_init(|| Mutex::new(HashMap::new())).lock().unwrap().clear();
    }

    #[test]
    fn token_bucket_lets_first_n_through() {
        fresh_buckets();
        let t0 = Instant::now();
        // Default-Limit für "test_code" ist (max=10, secs=60)
        for _ in 0..10 {
            assert!(try_consume_token("test_code", t0));
        }
    }
    #[test]
    fn token_bucket_drops_after_limit() {
        fresh_buckets();
        let t0 = Instant::now();
        for _ in 0..10 { try_consume_token("test_code", t0); }
        assert!(!try_consume_token("test_code", t0));
    }
    #[test]
    fn token_bucket_resets_after_window_without_sleep() {
        fresh_buckets();
        let t0 = Instant::now();
        for _ in 0..10 { try_consume_token("test_code", t0); }
        assert!(!try_consume_token("test_code", t0));
        // Simuliere "Zeit ist 61 sec spaeter" durch injected-clock — kein sleep
        let t_later = t0 + Duration::from_secs(61);
        assert!(try_consume_token("test_code", t_later));
    }
    // weitere Tests für consent-off, unknown-code-default, etc.
}
```

**Schicht 2 — Pro-Site Mock-Transport-Tests** in `client/src-tauri/src/sentry_init.rs` als zweites `#[cfg(test)] mod`. Nutzt **MockTransport** (Implementation des `sentry::transport::Transport`-Traits) der Events in `Arc<Mutex<Vec<Envelope>>>` sammelt statt zu HTTP zu posten. ~50 Zeilen Boilerplate, einmalig.

```rust
// in sentry_init.rs
#[cfg(test)]
mod mock_hub_tests {
    use super::*;
    use std::sync::{Arc, Mutex};
    use sentry::{ClientOptions, Hub, transport::Transport, types::protocol::v7::Envelope};

    struct MockTransport(Arc<Mutex<Vec<Envelope>>>);
    impl Transport for MockTransport {
        fn send_envelope(&self, env: Envelope) {
            self.0.lock().unwrap().push(env);
        }
    }

    fn run_with_mock<F>(f: F) -> Vec<Envelope>
    where F: FnOnce()
    {
        let captured = Arc::new(Mutex::new(Vec::new()));
        let transport = Arc::new(MockTransport(captured.clone()));
        let opts = ClientOptions {
            dsn: "https://x@example.invalid/1".parse().ok(),
            transport: Some(Arc::new(move |_| transport.clone() as Arc<dyn Transport>)),
            ..Default::default()
        };
        let client = sentry::Client::from(opts);
        Hub::run(Arc::new(Hub::new(Some(Arc::new(client)), Default::default())), f);
        Arc::try_unwrap(captured).ok().unwrap().into_inner().unwrap()
    }

    #[test]
    fn s1_pirep_fail_transient_event_survives_redact() {
        CONSENT.store(true, Ordering::Relaxed);
        let envelopes = run_with_mock(|| {
            emit(
                sentry::Level::Warning,
                "pirep_file_failed_transient",
                "PIREP file failed (transient)",
                &[
                    (tag_keys::ERROR_KIND, "http_5xx".into()),
                    (tag_keys::ERROR_STATUS_CODE, "503".into()),
                    (tag_keys::PIREP_ID, "test-id".into()),
                ],
            );
        });
        assert_eq!(envelopes.len(), 1);
        let event = extract_event(&envelopes[0]);
        // P0-Regression-Guard: ALLE drei Diagnose-Tags muessen NACH
        // redact_event noch da sein (= "error.kind", "error.status_code",
        // "pirep.id" sind in der Allowlist).
        assert_eq!(event.tags.get("error.code"), Some(&"pirep_file_failed_transient".into()));
        assert_eq!(event.tags.get("error.kind"), Some(&"http_5xx".into()));
        assert_eq!(event.tags.get("error.status_code"), Some(&"503".into()));
        assert_eq!(event.tags.get("pirep.id"), Some(&"test-id".into()));
        // Fingerprint-Vertrag: ["aeroacars", error_code]
        assert_eq!(event.fingerprint.as_ref(), &["aeroacars", "pirep_file_failed_transient"][..]);
    }
    // 9 weitere Tests, einer pro Site
}
```

### LE5 — Akzeptanz pro Site

Eine Site ist „done" wenn ALLE 4 Kriterien erfüllt sind:

| Kriterium | Wie verifizieren |
|---|---|
| (a) `cargo test` für Pro-Site MockTransport-Test grün (`s{N}_*_event_survives_redact`) | CI-Job-Status |
| (b) DEV-Trigger-Button löst sichtbares Event in `tip.kant.ovh` aus innerhalb 15 Sek | Manuell via VA-Owner-Browser auf tip.kant.ovh |
| (c) **P2-1-Fix: Allowlist-Compliance** wird IM Test (a) per MockTransport gegen das vor-`before_send` und nach-`redact_event` Tag-Set geprüft (KEIN Browser-DevTools — Sentry-Envelope geht aus Rust raus, nicht aus dem WebView) | Test-Assert `event.tags.keys().all(allowed_tag_keys.contains)` |
| (d) Rate-Limit greift (= 5× DEV-Button-Klick → max 1 Event pro Window in tip.kant.ovh) | DEV-Button 5× klicken, in tip.kant.ovh-Issue-Detail zählen |

Wenn (b) failt: Site rollt zurück bis (b) grün ist. Wir akzeptieren KEINEN „lokal grün, in tip.kant.ovh nicht sichtbar"-Status — das wäre der gleiche Bug-Mechanismus wie Svenny-Modal.

### LE6 — Reihenfolge & Commit-Slices

## Algorithmus (Helper-Funktionen)

### `emit()` — Kernfunktion (vollständig, R1-Stand)

```rust
// in client/src-tauri/src/sentry_init.rs (NEU)
use std::collections::HashMap;
use std::sync::{Mutex, OnceLock};
use std::time::{Duration, Instant};

#[derive(Debug, Clone, Copy)]
struct RateLimit { max: u32, secs: u64 }

#[derive(Debug)]
struct BucketState {
    tokens_remaining: u32,
    window_started_at: Instant,
    limit: RateLimit,
}

// P1-2-Fix: HashMap<String, _> statt HashMap<&'static str, _>. Vorher hätte
// die Map nur `&'static str`-Schlüssel akzeptiert; ein normales `&str`
// wäre nicht reingegangen. String ist marginal teurer (1 Allocation pro
// neuem error_code, danach wiederverwendet) und unifiziert das Lifetime-
// Modell.
static BUCKETS: OnceLock<Mutex<HashMap<String, BucketState>>> = OnceLock::new();

const RATE_LIMIT_DEFAULTS: &[(&str, RateLimit)] = &[
    ("pirep_file_failed_transient", RateLimit { max: 3, secs: 300 }),
    ("pirep_file_failed_hard",      RateLimit { max: 5, secs: 60 }),
    ("sim_disconnect",              RateLimit { max: 1, secs: 60 }),
    ("aircraft_mismatch",           RateLimit { max: 5, secs: 60 }),
    ("not_at_departure",            RateLimit { max: 5, secs: 60 }),
    ("hard_landing",                RateLimit { max: 10, secs: 60 }),
    ("update_check_failed",         RateLimit { max: 1, secs: 600 }),
    ("recorder_upload_failed",      RateLimit { max: 3, secs: 60 }),
    ("dds_violation",               RateLimit { max: 10, secs: 60 }),
];
const DEFAULT_LIMIT: RateLimit = RateLimit { max: 10, secs: 60 };

fn lookup_limit(error_code: &str) -> RateLimit {
    RATE_LIMIT_DEFAULTS.iter()
        .find(|(k, _)| *k == error_code)
        .map(|(_, l)| *l)
        .unwrap_or(DEFAULT_LIMIT)
}

/// P2-2-Fix: `now: Instant` als Parameter (Clock-Injection für Tests).
/// Production-`emit()` reicht `Instant::now()` durch.
fn try_consume_token(error_code: &str, now: Instant) -> bool {
    let mut buckets = BUCKETS
        .get_or_init(|| Mutex::new(HashMap::new()))
        .lock()
        .expect("rate-limit bucket mutex poisoned");
    let limit = lookup_limit(error_code);
    let entry = buckets.entry(error_code.to_string()).or_insert(BucketState {
        tokens_remaining: limit.max,
        window_started_at: now,
        limit,
    });
    if now.duration_since(entry.window_started_at) >= Duration::from_secs(limit.secs) {
        entry.tokens_remaining = limit.max;
        entry.window_started_at = now;
        entry.limit = limit;
    }
    if entry.tokens_remaining > 0 {
        entry.tokens_remaining -= 1;
        true
    } else {
        false
    }
}

/// Sentry-Event mit Rate-Limit + Allowlist-typed Tags + expliziter
/// Fingerprint-Gruppierung senden.
///
/// Returns `true` wenn an Transport übergeben, `false` wenn verworfen
/// (Consent aus, Rate-Limit, oder kein Sentry-Client gebunden).
///
/// **Privacy:** `tags` MÜSSEN aus `tag_keys::*`-Konstanten kommen — die
/// sind 1:1 mit der `allowed_tag_keys()`-Allowlist. Wenn jemand eine
/// neue Konstante ergänzt MUSS er auch die Allowlist erweitern, sonst
/// strippt `before_send` den Tag wieder weg.
///
/// **Grouping:** Fingerprint ist hart auf `["aeroacars", error_code]`
/// gesetzt — verhindert dass eine variierende Message (z.B. mit retry-
/// counter) pro Variation einen neuen Issue im GlitchTip-Dashboard
/// erzeugt.
pub fn emit(
    level: sentry::Level,
    error_code: &'static str,
    message: &str,
    tags: &[(&'static str, String)],
) -> bool {
    if !CONSENT.load(std::sync::atomic::Ordering::Relaxed) {
        return false;
    }
    if !try_consume_token(error_code, Instant::now()) {
        tracing::debug!(error_code, "[sentry] rate-limited — event dropped");
        return false;
    }
    sentry::with_scope(
        |scope| {
            scope.set_fingerprint(Some(["aeroacars", error_code].as_slice()));
            scope.set_tag(tag_keys::ERROR_CODE, error_code);
            for (k, v) in tags {
                scope.set_tag(*k, v);
            }
        },
        || {
            sentry::capture_message(message, level);
        },
    );
    true
}
```
